# Постоянные визуальные эффекты у NPC (столб света)

Речь про эффект, который висит на NPC всё время, пока он стоит в мире: столб
света с рунным кругом под ногами, огонь, свечение и прочее. Ничего на клиенте
править не нужно — всё это клиент Interlude умеет сам, ему только нужно
сказать.

Привязка живёт в датапаке, рядом с остальными свойствами NPC
(`data/xml/npcs/*.xml`), плюс есть админ-команда, чтобы подобрать эффект
живьём, не перезапуская сервер.

---

## 1. Два способа, и когда какой

**`visualEffect`** — маска `AbnormalEffect`, та самая, которой клиенту
рисуются баффы-дебаффы (кружок, огонь, лёд, магический круг). Уезжает
в поле `abnormalEffect` пакета `NpcInfo`, то есть **не стоит серверу ничего**:
ни таймеров, ни лишних пакетов. Держится вечно, переживает `stopAllEffects()`
и респавн. Это основной способ, начинать надо с него.

**`visualSkill`** — проигрывание анимации каста скилла по кругу
(`MagicSkillUse` каждые N мс). Нужно для эффектов, которых нет среди масок:
у клиента они существуют только как анимация конкретного скилла. Стоит
одного пакета на каждого, кто видит NPC, раз в период, и обычно тащит за
собой звук каста — поэтому это запасной вариант.

---

## 2. Как привязать

В блоке нужного NPC в `data/xml/npcs/*.xml`:

```xml
<npc id="30320" name="Richlin" title="Gatekeeper" alias="gatekeeper_richlin">
    <set name="type" val="Gatekeeper"/>
    <set name="visualEffect" val="magiccircle"/>
    ...
```

Это и есть живой пример из сборки: гейткипер Richlin (Гиран) стоит в столбе
света. Убрать — удалить строку.

Значение `visualEffect` — имя из таблицы ниже, либо маска вида `0x800000`,
либо несколько штук через `;` (`magiccircle;flame`). Ошибочное значение
пишет warning в лог и просто игнорируется.

`visualSkill` пишется как `id`, `id;level` или `id;level;период_в_мс`
(по умолчанию уровень 1, период 3000 мс, минимум 500):

```xml
<set name="visualSkill" val="1069;1;3000"/>
```

Важно: свойство привязано к **шаблону**, то есть эффект получат все NPC
этого id. Нужен эффект на одном конкретном — либо заводить отдельный
`<npc id="5000x" idTemplate="30320" ...>` (так сделаны кастомные NPC в
`50000-50999.xml`), либо ставить его скриптом/командой.

---

## 3. Таблица масок

Имена — из `AbnormalEffect` (`enums/skills/AbnormalEffect.java`), маски —
то, что понимает клиент Interlude.

| имя | маска | что рисует |
|---|---|---|
| `bleeding` | 0x000001 | капли крови |
| `poison` | 0x000002 | зелёный туман |
| `redcircle` | 0x000004 | красный круг под ногами |
| `ice` | 0x000008 | ледяная корка |
| `wind` | 0x000010 | ветер |
| `fear` | 0x000020 | страх |
| `stun` | 0x000040 | звёздочки над головой |
| `sleep` | 0x000080 | сон |
| `mute` | 0x000100 | немота |
| `root` | 0x000200 | корни |
| `hold1` | 0x000400 | паралич |
| `hold2` | 0x000800 | окаменение |
| `unknown13` | 0x001000 | — |
| `bighead` | 0x002000 | большая голова |
| `flame` | 0x004000 | пламя |
| `changetexture` | 0x008000 | смена текстуры |
| `grow` | 0x010000 | увеличение |
| `floatroot` | 0x020000 | подвешивание |
| `dancestun` | 0x040000 | оглушение танцем |
| `firerootstun` | 0x080000 | огненные корни |
| `stealth` | 0x100000 | невидимость |
| `imprison1` | 0x200000 | световая клетка |
| `imprison2` | 0x400000 | световая клетка (вариант) |

Столб света со скриншота — `magiccircle`. Соседние `imprison1`/`imprison2`
дают похожий, но более узкий и «клеточный» вариант; их стоит посмотреть
глазами и выбрать, что больше нравится.

## 4. Подбор эффекта живьём

Команда доступна с access level 7 (`adminCommands.xml`), работает по
**выделенному NPC** и меняет только его — до рестарта сервера. Чтобы
закрепить, найденное значение переносится в XML.

```
//npc_effect                             показать текущее состояние и подсказку
//npc_effect magiccircle                 надеть маску по имени
//npc_effect 0x800000                    то же самое маской
//npc_effect magiccircle flame           несколько сразу
//npc_effect none                        снять
//npc_effect skill 1069 1 3000           крутить анимацию скилла 1069 lvl 1 раз в 3 с
//npc_effect skill none                  прекратить
```

Соседняя `//abnormal <маска>` из aCis делает похожее, но по-другому: она
кладёт биты в обычные абнормалы цели и слетает при первом же пересчёте
эффектов. `//npc_effect` пишет отдельное поле, которое никакой пересчёт
не трогает.

---

## 5. Как это устроено

- `NpcTemplate` читает `visualEffect` / `visualSkill` (`parseVisualEffect`,
  `parseVisualSkill`) и отдаёт их `Npc` в конструкторе — дальше это уже
  свойство экземпляра, поэтому скрипт или GM может поменять его конкретному
  NPC (`setVisualEffect`, `setVisualSkill`).
- `Npc.getAbnormalEffect()` подмешивает маску поверх настоящих абнормалов —
  именно поэтому её не может стереть ни `stopAllEffects()`, ни истечение
  баффа. Пакет `NpcInfo` пишет результат в поле абнормалов как обычно,
  то есть трафик не меняется вообще.
- `setVisualEffect` дёргает `updateAbnormalEffect()`, а он рассылает
  `NpcInfo` всем, кто видит NPC, — эффект появляется/пропадает сразу.
- Скилловый вариант ведёт `NpcVisualEffectTaskManager`: тик раз в 500 мс,
  внутри — только те NPC, у которых `visualSkill` реально задан (у остальных
  накладных расходов нет вообще, они в него не попадают). Регистрация в
  `Npc.onSpawn()`, снятие — в `Npc.onDecay()`. `hitTime` в `MagicSkillUse`
  равен периоду, чтобы между повторами не было провала.

---

## 6. Ограничения

- Маски — ровно 24 штуки из таблицы, своих клиент не знает: старшие биты
  он просто игнорирует.
- Эффект видит только тот, у кого NPC в knownlist; при входе в зону
  видимости он приходит вместе с `NpcInfo` (у скиллового варианта — с
  задержкой до одного периода).
- `visualSkill` шлёт пакет каждому зрителю каждый период. На людном городском
  NPC период меньше 2–3 секунд лучше не ставить.
- Правка через `//npc_effect` не сохраняется: перезапуск сервера вернёт то,
  что написано в XML.

## 7. Что из эффектов вообще есть в клиенте

Разведка по клиенту (`E:\client`), чтобы не гадать, какой скилл какую картинку
даёт.

### Где они лежат

`system/LineageEffect.u` — пакет Unreal 2 (version 123, licensee 30), в нём
**864 класса эффектов**, собранных из 2411 `SpriteEmitter`, 1232 `MeshEmitter`,
36 `VertMeshEmitter`, **29 `BeamEmitter`** и 1 `RibbonEmitter`. Ещё эффекты
живут в `LineageMonster*.u`, `LineageNpc*.u`, но там они привязаны к моделям.

Список классов снимается своим парсером пакетов:

```
powershell -ExecutionPolicy Bypass -File tools/client/dump_package.ps1 ^
    -Package "<client>\system\LineageEffect.u" -ClassesOnly
```

### Как скилл выбирает эффект

Имя класса собирается как `<категория>_<имя скилла в snake_case>_<ca|ta>`, где
категория — префикс из колонки `desc` в `skillgrp.dat`, `ca` играет на кастере,
`ta` — на цели. Проверено на трёх независимых парах:

| скилл | `desc` в skillgrp | класс в LineageEffect.u |
|---|---|---|
| 1043 Holy Weapon | `skill.white.1043` | `wh_holy_weapon_ta` |
| 1172 Aura Burn | `skill.el.1172` | `el_aura_burn_ca` / `_ta` |
| 277 Dance of Light | `skill.phenomenon.277` | `ph_dance_of_light_ta` |

Для NPC кастер и цель — он сам, поэтому любой такой класс поднимается сервером
через `visualSkill` / `//npc_effect skill <id>`, **не трогая клиент вообще**.

### Кандидаты на луч

864 класса отфильтрованы по наличию `BeamEmitter` и сопоставлены с
`skillname-e.dat`:

| skill id | скилл | класс эффекта |
|---|---|---|
| 1011 | Heal | `wh_heal_ta` |
| 1013 | Recharge | `wh_recharge_ta` |
| 1044 | Regeneration | `wh_regeneration_ta` |
| 1335 | Balance Life | `wh_balance_life_ta` |
| 1016 | Resurrection | `wh_resurrection_ta` |
| 1031 | Disrupt Undead | `wh_disrupt_undead_ta` |
| 1043 | Holy Weapon | `wh_holy_weapon_ta` |
| 1231 | Aura Flare | `el_aura_flare_ta` |
| 1172 | Aura Burn | `el_aura_burn_ca` |
| 277 | Dance of Light | `ph_dance_of_light_ta` |

**1011 (Heal) визуально подошёл** — это и есть столб света; открытый вопрос по
нему в разделе 8.

### Чего скиллом не достать

`e_u061_beam`, `s_u805_channeling` / `s_u806_channeling_beam` (по имени — как
раз постоянный луч-канал), `m_u*`, `mb_frintessa_field_*` — у них нет имени
скилла, значит через `MagicSkillUse` они не поднимаются. У NPC-скиллов своя
таблица `mobskillanimgrp.dat` (`npc_id` + `skill_id` → имя эффекта, 506 разных
имён) — туда можно дописать строку под свой npc id, но это уже правка dat'а.

### Инструменты, которыми это снималось

- **dat'ы этого клиента перешифрованы «новой» RSA-парой l2encdec**, а не
  оригинальными ключами NCsoft: `l2encdec -l` падает на распаковке, работает
  `-d`. Обратно — `-e 413`.
  ```
  E:\l2encdec\l2encdec.exe -d skillgrp.dat skillgrp.dec
  ```
- `l2disasm` + готовые определения Interlude превращают dat в TSV (и `l2asm`
  собирает обратно):
  ```
  E:\L2FileEditor\data\l2asm-disasm\l2disasm.exe ^
      -d DAT_defs\Interlude\skillgrp.ddf skillgrp.dec skillgrp.txt
  ```
  Так сняты `skillgrp` (30 599 строк), `skillname-e` (2117 скиллов),
  `mobskillanimgrp`.
- `tools/client/dump_package.ps1` — разбор таблиц имён/импортов/экспортов
  любого `Lineage2Ver111` пакета.
- `E:\UnrealEditor\System\UCC.exe` — L2-кит с ucc и UnrealEd на месте, то есть
  свой класс эффекта (наследник `Emitter` с системой частиц в
  `defaultproperties`) можно собрать в отдельный пакет, если готовых не хватит.

## 8. Открытый вопрос: NPC изображает каст

`//npc_effect skill 1011 1 1500` даёт нужный столб света, **но NPC при этом
стоит в позе каста** — а он должен просто стоять.

Причина двойная:

1. `skillgrp.dat` держит для скилла букву анимации каста — у 1011 это
   `ani_char = 'D'`, клиент её и проигрывает.
2. Наш `MagicSkillUse` шлёт `hitTime` равным периоду (это сделано, чтобы луч не
   мигал между повторами) — то есть поза каста растянута на весь период.

Зацепки, по возрастанию цены, ни одна пока не проверена:

- **`hitTime`.** Послать 0 или что-то маленькое и посмотреть, что станет с
  анимацией и не начнёт ли моргать сам луч. Правка в одну строку в
  `NpcVisualEffectTaskManager`.
- **Скилл без анимации.** В `skillgrp` **10 661 строка из 30 599 с пустым
  `ani_char`** — у таких скиллов анимации каста нет вообще. Найти среди них тот,
  чей эффект похож на 1011, и брать его.
- **`MagicSkillLaunched` вместо `MagicSkillUse`.** Проверить, играет ли клиент
  эффект попадания сам по себе, без анимации каста.
- **Своя строка в `skillgrp.dat`** (уровень «правка клиентских данных»): копия
  строки 1011 под свободным id, с пустым `ani_char` и своим `hit_time` — эффект
  тот же, NPC стоит смирно. Собирается `l2asm` + `l2encdec -e 413`, игроки
  забирают новый `skillgrp.dat`, значит `CLIENTVER_VALUE` и `ClientVersion`
  поднимаются вместе.
- **Маска абнормала** (`magiccircle`, уже работает) анимации не даёт вовсе — но
  выбор ограничен 24 битами из раздела 3.
